> 编号 **09** ｜ 类型：**实现计划** ｜ 上游：`08-后端架构设计.md`（已评审，决策见其 §13）

## 全程铁律（每步都适用）

1. **不改现有测试的断言**：`scripts/self_check.py`、`scripts/smoke_app.py` 是回归护栏；
2. **同名适配层**：`db.load_db() / store.* / profile.*` 的签名与语义完全不变，只换实现；
3. **开关可回退**：`STORAGE=json|db`（P0）、`USE_API=0|1`（P1）；任何一步出问题，一条环境变量回到上一状态；
4. **数据先备份**：动 JSON → DB 之前，先 `data/backup/<时间戳>/` 备份三个 JSON；
5. **每步一个提交**，提交信息写清"改了什么 + 验证命令 + 结果"。

七步全部完成，出口标准达标。

| `pytest tests` | 13 / 0 | 13 / 0 |

（DB 模式少的那几项是文件级断言与"空状态"场景，按设计跳过，代码里都有注明。）

**与原计划的差异（都是变好，不是妥协）**：

1. **`migrate.ensure_schema()` 会认老库**：P0-2/P0-5 期间用 `create_all()` 建的库没有 `alembic_version`，
   直接 `upgrade head` 会撞"表已存在"。现在自动判断三种起始状态（空库 / 有业务表无版本表 / 有版本表），
   老库只 `stamp head` 补记版本号，**不动数据**；`create_all()` 从此只出现在测试里。
2. **`SMOKE_STORAGE=db` 改用 Alembic 建临时库**：这样这条冒烟顺带证明了"迁移建出来的库能驱动整个界面"，
   而不是只证明 `create_all` 建出来的库能用。
3. **迁移等价性由测试守住**：`tests/test_migrations.py` 把 `upgrade head` 建出的 schema 与
   `Base.metadata.create_all` 建出的 schema **逐表/逐列/索引/外键**比对，ORM 一改而迁移没跟上就会红。
4. **顺手修掉一个假失败**：本机沙箱下 `tempfile.mkdtemp` 的 `0o700` 目录建完就不可访问，
   导致 AppTest 退出时打一串 `PermissionError`（断言其实全过）。见 `docs/07` §6.8。

**新增/改动文件**：`alembic/`（`env.py`、`script.py.mako`、`versions/0001_init.py`）、`alembic.ini`、
`recipe_planner/storage/migrate.py`、`tests/test_migrations.py`、`recipe_planner/storage/import_json.py`（改走 Alembic）、
`scripts/smoke_app.py`（改走 Alembic + 修临时目录）、`requirements.txt`（固定版本）、`docs/07`。
