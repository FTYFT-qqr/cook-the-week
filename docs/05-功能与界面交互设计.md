## 0. 设计前提：为什么把它改成"以今晚为中心"

你选的场景是**自己和家人真实使用**。这一条推翻了三个默认假设：

| 原来的默认假设 | 真实使用下的结论 |
|---|---|
| "要让评审/面试官看见 agent 在工作" | 不再重要 → **"开发者视角（候选数/修正轮数/LLM/耗时）"从常规界面撤出** |
| "用户打开是为了排一周" | 打开频率最高的时刻是**今天做饭前** → **首页必须是"今晚"**，不是"填需求" |
| "功能多、看得见过程 = 好 demo" | **耐用 > 惊艳** → 结果要可复现、改一处不能动整周、关掉明天还在 |

**家庭真实使用的周循环**（所有功能按这条节奏切，不按技术模块切）：

> **周日排一次** → **每天傍晚看一眼** → **买菜时打勾** → **偶尔改一处** → **下周复用**

## 1. 功能地图

### 1.1 Demo 必做：5 个功能模块

| 编号 | 模块 | 服务的动作 | 一句话职责 |
|---|---|---|---|
| **M1** | **今晚**（首页） | 每天傍晚看一眼 | 打开就知道今晚吃什么、要多久、多少钱，并且能**就地改一处** |
| **M2** | **排一周**（动作页，不占导航） | 周日排一次 | 填需求 → 生成一周菜单；首次使用由它引导 |
| **M3** | **本周计划** | 看一眼 / 改一处 | 7 天一览 + 点开某天看详情与逐道反馈 + 以前的方案 |
| **M4** | **买菜清单** | 买菜时打勾 | 一行一样、点一下打勾、已买沉底、能带走（复制/CSV/A4 打印） |
| **M5** | **口味档案** | 下周更懂我 | 喜欢/不喜欢两个列表 + 全库浏览标记 + 来源痕迹 |

### 1.2 横切交互：两个必须成规则的东西

**A. "改一处" —— 三个固定入口，不做自由对话**

| 入口 | 出现在哪 | 作用范围 |
|---|---|---|
| `回家晚了` | 今晚页 | 只把**今晚**换成最快能做完的组合 |
| `来客人了` | 今晚页 | 只改**今晚**的人数与份量，并给一条"临时补买"提醒 |
| `这道不想吃` | 今晚页每道菜 / 本周详情每道菜 | 只换**这一道**，并记进口味档案 |

**B. 八条不变量** —— 见第 4 节。这是整个 demo 的信任基础，任何新功能都不许违反。

### 1.3 Demo 可选（先留位置，不急着做）

| 功能 | 为什么可以晚一步 |
|---|---|
| 做完标记 + 一句评价（好吃 / 一般 / 下次不做） | 是"越用越懂你"最便宜的闭环，但不是主线 |
| 定住某道菜 / 允许一周吃两次 | 提升掌控感，可后置 |
| 家人多成员（各自忌口） | 真实需要，但会牵动档案结构，建议第二批 |

### 1.4 明确不做（连界面都不留，防止后面又加回来）

| 不做 | 理由 |
|---|---|
| 自由对话改需求 | 家人自用会觉得不可预测：想改一处却要先想"怎么说" |
| 账号 / 云端同步 | 一台设备、本机保存足够 |
| 开发者视角面板 | 自用只有干扰 → 撤出常规界面 |
| "手机视图"手动开关 | 改成按窗口宽度**自动适配**，不让家人去侧栏找开关 |
| 精确营养计算 | 只做方向性标签 + 诚实措辞（"按菜品标签推荐，不等于营养计算"） |

## 2. 页面结构与导航

### 2.1 四个页面 + 一个动作页

```
🏠 今晚            🗓️ 本周计划         🛒 买菜清单         ❤️ 口味档案
（默认首页）        （7 天一览+详情）    （到店打勾）        （长期资产）

                    📝 排一周  ← 动作页：不占导航，有"返回"
```

### 2.2 导航规则

- 导航固定 **4 项**，顺序如上；**默认落在"今晚"**。
- 当前所在页高亮；**任何页面都不再出现第五个导航项**。
- "排一周"的入口只有两个：① 今晚页在"还没有方案"时的引导卡；② 本周计划页的`重新排一版 / 改需求`。

> **变更记录（2026-09-11，产品负责人决定，覆盖上面第 1、3 条）**
> 实际使用后决定：**「排一周」加回左栏任务栏，成为第 3 项**，导航共 **5 项**：
> `今晚 / 本周计划 / 排一周 / 买菜清单 / 口味档案`，默认仍然落在「今晚」。
> 理由：入口太深——已有方案时只能在「本周计划」里找`改需求`，家人在「今晚」页找不到"重新排一周"的地方；给一个常驻入口比多一次跳转更值。
> 上面第 2 条（当前页高亮、不出现更多导航项）仍然有效；2.3 的"不给首屏塞 12 个输入框"结论不变（默认首页仍是「今晚」，表单只在点进「排一周」后出现）。

### 2.3 为什么要给"排一周"降级（已部分回调，见上方变更记录）

一周只填一次的东西，不该占一个永久入口；而一周要打开七次的"今晚"，现在恰恰没有入口。更实际的问题是：**家人每次进来都要先面对 12 个输入框，会直接被劝退**。

### 2.4 与当前运行版本的差异（这就是要改的东西）

| # | 现在 | 设计目标 | 为什么 |
|---|---|---|---|
| 1 | 导航第一项是`需求 & 生成` | 改成`今晚`；`排一周`变成动作页 | 见 2.3 |
| 2 | "今晚大卡"在**本周菜单页顶部**，且三个按钮只能作用于**今晚第一道** | 独立成**今晚页**，作用于**今晚每一道** | 一眼看今晚是最高频动作，不该埋在第二页；今晚有两道菜时只想换第二道现在做不到 |
| 3 | 改动只有`换一道 / 喜欢 / 不喜欢` | 增加`回家晚了` / `来客人了` 两个整卡级快改 | 覆盖家庭最常见的两个真实打断 |
| 4 | "开发者视角"在`更多操作`折叠区里 | 从常规界面撤出 | 家人不需要，且它会把注意力从菜单上带走 |
| 5 | `手机视图`手动开关 | 保持"按宽度自动"（已在 `06` 规范里） | 确认即可，无需改动 |
| 6 | 逐道反馈"只动这一道" | **保持不动**（这是已经做对的地方） | 见不变量 R1 |

## 3. 交互设计（M1–M5）

### M1 · 今晚（首页）

**触发**：打开应用；或点导航`今晚`。

**正常状态（今天有安排）**，从上到下：

1. 一行小字：`方案 9/14–9/20 · 9-10 生成`
2. **主角（首屏唯一焦点）**
   - 一行主色小字：`今晚 · 周三 9/17`
   - 菜名（22px）：`清蒸鲈鱼、蒜蓉西兰花`
   - 一行：`约 45 分钟 · 预计 ¥62`
   - 一句理由（只留今晚第一道的理由，不要堆两句）
3. **每道菜一行**：菜名 + `这道不想吃`（次级、低对比）
4. **两个快改**：`回家晚了` ｜ `来客人了`
5. **开始做饭** → 展开「怎么做」：先做什么（下锅顺序）→ **每道菜 3–5 步**（docs/12 阶段三）→ 参考视频入口
6. **做完了** → 标记今天完成（进入下面的状态③）

**五种状态，每一种都必须有交代**：

| 状态 | 界面说什么 | 可做的动作 |
|---|---|---|
| ① 今天有安排 | 如上 | 换一道 / 不想吃 / 回家晚了 / 来客人了 / 开始做饭 / 做完了 |
| ② 今天已跳过 | `今晚不做饭（你标记过）` | `↩️ 撤销`、`去看本周计划` |
| ③ 今天已做过 | `周三已做：清蒸鲈鱼、蒜蓉西兰花` | `看看明天`、`再做一次` |
| ④ **还没有这一周的菜单** | 引导卡：`还没有这周的菜单` + `帮我排一周 →` | 走 M2（这是唯一一次把表单摆到首屏） |
| ⑤ 这一周已结束 | `上周（9/7–9/13）的菜单在这里` | `照上周再来一份`、`重新排一周` |

**边界与失败**：

- `回家晚了` 换不出更快的菜 → 就地给可点击选项：`放宽到 30 分钟` ｜ `今晚只做一个菜`。
- `来客人了` → 只改今晚份量提示 + 一条`临时要补买：X、Y`，**不动整周清单**、不重排其他天。
- 已晚于今天（过了晚上 22:00）→ 首页默认切到**明天**，并用一行小字说明（避免"今天已经过了还在提示今晚吃什么"）。

### M2 · 排一周（动作页）

**触发**：今晚页状态④的引导卡；或本周计划页的`重新排一版 / 改需求`。

**界面**：4 组表单（`人数与天数` / `口味与忌口` / `时间与预算` / `家里已有`）+ 3 张场景快填卡（首屏视觉锚点）；每组 2–3 个字段，**每行填满，不留空洞**。

**交互流程**：

1. 提交 → **阶段反馈**（正在挑菜 → 正在搭配 → 正在检查忌口和预算 → 正在算清单），可取消；
2. 完成 → 自动跳到`今晚`（首次）或`本周计划`（已有方案时重排）；
3. 完成 → 一条确认：`已排好 9/14–9/20 的 7 天晚餐` + `看看这一周`；
4. 若已存在方案 → 必须明确说：`已另存为新的一版，旧版在「以前的方案」里`。

**失败**：绝不给"候选已用完"这种结论句，而是给**可点击的下一步**：`时长上限放宽到 60 分钟` ｜ `预算加 20 元` ｜ `某天少排一道菜`。

**规则**：重排 = **整周都会变**，所以必须显式告知，且不能被"改一处"误触发。

### M3 · 本周计划

**顶部**：方案名 + 日期范围 + `重排一版` / `改需求`（两个次级按钮）。

**整周一览（折叠，默认收起）**：7 个等宽天行 —— `周三 9/17`（定宽）｜ 菜名（弹性）｜ `45 分钟 · ¥62`（右对齐）。
想"一眼扫七天"时开它；它是**扫读**用的，不做逐道操作。

- **今天**：主色浅底 + `今天` / `今晚` 标记
- **已过的日子**：整体降到 55% 透明 + `已过`

**选看哪一天（一排胶囊，2026-09-14 起）**：

> 起因是真实使用反馈：**一天一段一路铺下来，周五想翻到周末要往下滚很久。**

- 选项 = **天数**（第 1 天…第 N 天，有几天的方案就有几个），**与顿数无关**；
- 选项文字带 `周几 + 日期`，并把状态点出来：`今天 · 周五 9/18`、`周三 9/16 · 已过`；
- **默认停在今天**；今天不在这份方案里（排的是下周 / 这周已过）就停在第 1 天；
- 切换只换显示哪一天，**不改任何数据**；
- 已过的日子**仍然点得到**（回去看那天吃了什么），但只读。

**当天（主体，一次只显示这一天）**：

- **段头**：`第 3 天 周三 9/16` + `今天`/`已过` 标记 + 当天合计（只做一顿时 `合计约 45 分钟 · ¥62`；
  一天多顿时改成 `3 顿 · 合计 ¥96` —— **不把三顿的做菜时间加成一个数**）；
- 段内**一顿一张卡**（早/午/晚）：餐名 + `约 15 分钟 · ¥12` + `按 2 人算`，
  逐道卡片（菜名 + 3 个中性芯片 + 一句理由 + `换一道 / 定住 / 喜欢 / 不喜欢`），
  `有汤/炖菜可以先上火`（有则显示），**`怎么做（N 步 · 含参考视频）`**（折叠：
  先做什么 → 每道菜 3–5 步 → 参考视频入口。docs/12 阶段三把原来的`下锅顺序`并进了这一块）；
- **已跳过**的那一顿：卡里写`这顿不做饭`，并给一个`改回来做`；
- **已过的日子**：只读 —— 不给逐道操作按钮，段头写`已经过去了，只能看不能改`。

**底部折叠区**：`以前的方案 / 改动历史`（切换 / 复用 / 删除，删除要二次确认）。

**失败**：换不出菜时就地给放宽选项（同 M2），不把人赶回表单。

> **变更记录（2026-09-14）**：本节原来写的是"7 个等宽天行 + 点开某天看详情"（标签页式）。
> 实现早已往前走成"一天一段 + 一顿一张卡"，这次按真实使用反馈又加了**选天胶囊**，
> 本节据此回填为现状。逐条依据见 `docs/10-全天菜单设计.md` §⑦/§⑨。

### M4 · 买菜清单

**到店模式**（默认）：

- 一行一样：`☐ 西红柿　1.2 斤`；"用于哪几道菜"收进悬停提示，**不占第二行**；
- 分类用中性灰条分隔，**有内容才占位**；
- 已买的行**沉到该分类末尾**并整体降透明度；
- 顶部：细进度 + `已买 X / N 样，还剩 Y 样`；
- 底部固定操作条：`清除勾选`（次级）｜`带走清单`（主按钮 → 复制文本 / 导出 CSV / A4 打印）。

**交互细节**：

- 勾选状态**在本周内保留**（关掉浏览器再打开还在）；**切换方案时清空**，并给一句说明；
- 家里已有库存覆盖的食材单独一行小字列出，**不进采购清单**；
- 全部买齐 → `清单已全部买齐` + 一句"可以开始做饭了"；
- `带走清单` 的文本版**不带按钮、不带 emoji**，方便直接发微信给家人代买。

### M5 · 口味档案

**两块内容**：`我的喜好列表`（两个独立、可互相移动、可移除的列表）+ `全部菜品挑选`（按分类/关键词浏览并逐道标记）。

> **第三块（2026-09-15 起，`docs/12` v6）**：**`最近的吃法`** —— 首页在两者之间。
> 三堆：**最近常吃**（近两周吃过两次以上）/ **好久没吃**（上次吃在一个月以前）/ **刚开始爱吃**
> （只吃过一两次且就在这两周）；每道菜带「习惯 / 偶尔」与"吃过几次、上次多少天前、平均每隔几天"。
> **口径是"吃过"**：点过「做完了」或给这顿打过分才算；**排进菜单不算**（排了还没下锅）。
> 「不喜欢」的菜不进「好久没吃」—— 用户说过不要，再提醒就是顶嘴。
> 没有记录时不给空的假面板，直接说清"点「做完了」就会开始记"。

**必须补上的三处**：

1. **来源痕迹**：每条偏好后面写清"什么时候、在哪来的"（如 `8/10 在菜单里点的收藏`），让这个列表变成"我的记忆"而不是一个无来历的清单；
2. **就地说明临时与记住的差别**：一行小字——`换一道 = 只换这次，不影响档案；不喜欢 = 以后都不再出现`；
3. **导出 / 清空 / 隐私**：给出这三个按钮，而不是把文件路径暴露给用户；清空要二次确认。

## 4. 八条不变量（信任规则）

> 任何新功能都必须遵守；违反了就是 bug，不是"设计取舍"。

| # | 不变量 | 为什么 |
|---|---|---|
| **R1** | **单点改动只影响单点**，永不整周重排（除非用户明确点"重新排一版"） | 这是"我敢乱点"的前提 |
| **R2** | 每个动作都有**确认回执**（说清动了什么、没动什么）+ **可撤销** | 用户要知道刚才发生了什么 |
| **R3** | 破坏性动作（清空档案 / 删除方案 / 清除勾选）**二次确认** | 误点一次不能毁掉积累 |
| **R4** | 任何时候"我改不了"，都要给**可点击的下一步**，而不是一句结论 | 不把难题甩回给家人 |
| **R5** | **结果可复现**：同一需求 + 同一档案 → 同一份菜单；"再给我一版"才会变 | 结果每次都不一样会失去信任 |
| **R6** | **忌口永不妥协**，并且要用文字明确告诉我"已避开" | 安全是底线，不能靠用户自己核对 |
| **R7** | 所有数字都带**口径**（按 2 人份折算 / 以当地物价为准 / 按标签估算） | 对不上账就不再有信任 |
| **R8** | **状态永远可见**：今天第几天、哪些已做、哪些已跳过 | 一份菜单要变成"我的这一周" |

> **R6 的实施口径（2026-09-14 补，依据 `docs/12` §3.5 的实测）**：
> 「忌口」判的是**这道菜实际含什么**，不是**字段里填了什么**。
> 隐性来源（调味料里的过敏原）必须一并算进去 —— 食材写的是「蚝油」「生抽」「蒸鱼豉油」，
> 永远不会出现「海鲜」二字，所以：
> ① 建一张**隐性来源关键词表**（`recipe_planner/allergens.py`）并接进判定；
> ② 关键词只收**含义明确**的词（不收「鱼」「豆」「面」「麦」这类会误伤的裸字；
> 「紫菜/海带」是藻类不算海鲜；「淀粉」含义不明 → 回到数据层把写法写准确）；
> ③ 每道菜仍要人工填 `allergens`（LLM 排菜时看的是这个字段，填准能省掉一整轮修正）。
> 该口径下**候选池会变小**（实测：海鲜过敏 16→14、海鲜+蛋+新手 10→8）——
> 这是"安全优先于选择面"的代价，也是 `docs/12` 阶段一必须扩库的原因。

## 5. 状态与文案规范

### 5.1 四类状态各自必须有什么

| 状态 | 必须包含 | 不允许出现 |
|---|---|---|
| **空** | 一句现状 + **一个下一步按钮** | "暂无数据" |
| **加载** | 阶段文字（在做什么）+ 可取消 | 只有一个转圈 |
| **失败** | 说人话的原因 + **可点击的补救项** + 已有结果不丢 | 报错码、英文、把选择权甩回用户 |
| **成功** | 一条确认：**动了什么、没动什么** | 只弹"操作成功" |

### 5.2 用词表（把工程词换成家人的话）

| 不出现 | 换成 |
|---|---|
| 约束 / 硬约束 | 你的要求 |
| 候选（不足） | 能选的菜（不够了） |
| 校验 / 命中率 | 检查 / 有没有踩到你的忌口 |
| 兜底 / 降级 | 换了个更保险的排法 |
| LLM / Agent / 模型 | （不出现） |
| 会话 / 方案 id | 这一周 / 方案 |

### 5.3 按钮与确认文案规则

- 按钮用**动词开头**、**不超过 4 个字**（`换一道`、`开始做饭`、`带走清单`）；括号里的解释一律移到按钮上方的小字。
- 确认文案统一句式：**`已<做了什么>，<哪里没动>`**（例：`已把周三的「宫保鸡丁」换成「番茄炖牛腩」，其他六天没动`）。
- 按钮与标签里**不放 emoji**（全站只保留 ❤️ 收藏 / 📌 定住两个符号，且不进按钮文字）。

## 6. 家人共用的特殊考虑

1. **一台设备 = 一份家庭档案**：不做多人切换（避开），但所有"临时调整"必须和"记住偏好"在视觉上分得开（见 R1 与 M5 第 2 条）。
2. **代买场景**：`带走清单` 的文本要能被家人直接用——一行一样、带数量、不带任何界面味道。
3. **忌口是全家最敏感的一项**：有忌口设置时，本周计划顶部**恒常**显示一行`已避开：海鲜`；一旦真出现冲突，用最高优先级（红色 + 字重 600）呈现，且**不允许**以"部分满足"淡化。
4. **不假设使用者会读说明**：任何关键差别都要**就地一行小字**（如"换一道不影响偏好"），不放在帮助页里。

## 8. 体验验收清单（设计是否成立，逐条自问）

1. 周三下班打开，**3 秒内**知道今晚吃什么吗？
2. 只换今晚一道菜，**其他六天真的没动**吗？
3. 关掉页面、明天再打开，**还是我的那一周**吗？
4. 在超市**单手**能不能一屏内勾掉一样买好的菜？
5. 家人能不能只看**一张纸**（A4）就买齐、照着做？
6. 任何一次改动，我知不知道"**动了什么、能不能撤**"？
7. 排不出来时，我有没有**可以点的下一步**（而不是一句结论）？
8. 一屏之内，有没有出现**我看不懂的词**？
