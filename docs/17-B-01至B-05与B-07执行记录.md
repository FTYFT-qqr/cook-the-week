# 17 · 服务化收尾（B-01～B-05、B-07）执行记录

> 更新：2026-09-20 ｜ 本文只记录本轮已实际落地的旧文档未完成项；B-06 与 A6 不在本轮虚标完成。

## 已完成

| 项目 | 实现 | 验收 |
|---|---|---|
| B-01 幂等键生命周期 | `PlanJob` 为一次界面排菜操作持有一个稳定 key；`create_plan()` 支持显式复用 | 客户端单测 + API 幂等回归 |
| B-02 可信限流身份 | `AUTH_MODE=off` 时忽略伪造的 `X-API-Key`，按来源 IP 限流；启用认证后才按已认证 key 分桶 | middleware 单测 + 限流回归 |
| B-03 遗留任务收尾 | API 启动时将数据库/内存中遗留的 `queued/running` 任务标记为 `failed/server_restarted`，保留人话重试入口 | `JobRepo.reap_orphans()` 回归 |
| B-04 SSE 终态回查 | SSE 断流后回查 `GET /jobs/{id}`；若服务端已结束，以服务端终态为准 | 客户端断流终态单测 |
| B-05 缓存隔离 | 方案列表、方案详情、档案缓存的读写边界均使用深拷贝，调用方修改返回值不会污染缓存 | 客户端缓存回归覆盖 |
| B-07 导出标准 | CSV 的“是否已买”改为纯文本“是”；文本导出继续使用 `[x]`，A4 打印继续使用黑白方框 | 导出 API 与 self-check 回归 |
