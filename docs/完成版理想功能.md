# 📋 菜单推荐系统设计方案总结

> 以下是根据你之前的设想整理的完整设计方案，便于日后查阅与迭代。

---

## 🎯 一、核心目标

构建一个**个性化菜单推荐系统**，通过持续记录用户对菜品的每一次选择，动态调整菜品权重，从而判断用户是“偶尔心血来潮”还是“每天都要吃”，让推荐结果**越来越接近用户的真实喜好**。

---

## 🧠 二、核心设计思路

**RAG + 动态权重 + 时间衰减 + 频次稳定度**

- 用 **RAG（检索增强生成）** 存储和检索用户偏好。
- 每次用户选择/跳过某道菜，**实时更新该菜品的权重**。
- 权重不仅看“选了多少次”，还看 **“什么时候选、间隔多久、是否规律”**。
- 最终推荐时，按权重排序，优先推荐高权重菜品。

---

## ⚙️ 三、关键机制

### 1. 事件记录

每次用户行为都记录一条带时间戳的事件：

```json
{
  "user_id": "user_123",
  "dish_id": "dish_456",
  "action": "selected",   // 或 skipped / rated
  "timestamp": "2026-09-14T12:30:00",
  "context": { "meal": "lunch", "party_size": 1 }
}
```

### 2. 权重更新公式（简化版）

```
菜品权重 = 基础权重 
         × 时间衰减因子 
         × 频次稳定度 
         × 反馈方向
```

| 因子 | 作用 | 示例 |
|------|------|------|
| **时间衰减** | 越久远的行为影响越小 | 7天内 1.0，30天前 0.5，90天前 0.2 |
| **频次稳定度** | 区分“偶尔”和“习惯” | 每周都点 → 稳定度高；一年一次 → 稳定度低 |
| **反馈方向** | 点了加分，跳过减分 | 点 +1，跳过 -0.5，差评 -2 |

### 3. 如何区分“心血来潮”与“每天都要吃”？

**核心指标：时间间隔的规律性（方差）**

| 模式 | 特征 | 判断 |
|------|------|------|
| 每天都要吃 | 间隔 1 天，连续多天 | 强习惯，权重高且稳定 |
| 每周一次 | 间隔 7 天，规律 | 稳定偏好，权重中等偏高 |
| 偶尔心血来潮 | 间隔不规律，很久才一次 | 弱偏好，权重低且波动大 |
| 最近突然爱吃 | 近期频次飙升，历史无 | 短期热度，先高后衰减 |

**稳定度计算（变异系数法）：**

```python
import numpy as np

def stability_score(timestamps):
    if len(timestamps) < 3:
        return 0.3
    intervals = np.diff(sorted(timestamps))
    cv = np.std(intervals) / np.mean(intervals)
    return 1 / (1 + cv)   # cv 越小越稳定，映射到 0~1
```

## 🔄 四、完整操作流程

```
用户点餐
    ↓
记录事件（时间、菜品、反馈）
    ↓
更新该菜品权重：
    新权重 = 旧权重 × 衰减 + 本次反馈 × 稳定度
    ↓
存入用户偏好库（向量数据库 + 结构化字段）
    ↓
下次推荐时：
    检索用户偏好 → 按权重排序 → 生成推荐
```

```python
def update_preference_node(state):
    dish_id = state["selected_dish"]
    timestamp = state["timestamp"]
    
    history = store.get(("preferences",), f"{user_id}:{dish_id}")
    
    new_weight = calculate_weight(history, timestamp)
    
    store.put(("preferences",), f"{user_id}:{dish_id}", {
        "weight": new_weight,
        "last_selected": timestamp,
        "total_count": history.get("total_count", 0) + 1,
        "timestamps": history.get("timestamps", []) + [timestamp]
    })
    
    return state
```

- 用 **`store`** 存长期偏好（跨会话）
- 用 **`checkpointer`** 存对话历史
- 用 **RAG 检索** 偏好作为推荐依据
- 用 **反馈节点** 记录用户反应，持续更新

## 🚀 七、可优化方向

| 方向 | 说明 |
|------|------|
| **自适应学习** | 让系统自动学习衰减速率和稳定度阈值，而非手动设定 |

| **强化学习** | 用多臂老虎机平衡“利用已知喜好”和“探索新菜品” |
